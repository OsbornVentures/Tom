      How do I check for updates without losing my work?

      In Settings, choose Check for updates. Tom compares its version with published releases from OsbornVentures/Tom on GitHub, including beta releases for this beta build. The check sends no conversation or preferred-name data. An offline or failed check cannot establish that you are up to date.

      Download the new Network or Offline installer, quit Tom and its tray helper, then select the same installation folder. Setup verifies replacement files and retains conversations, settings, the preferred name, optional models, and personal files outside its shipped manifest. Back up important files first.       What can I use Tom for?

      Start with a clear, manageable task and a result you can inspect. The model, available tools, permissions, and your computer all affect what Tom can finish.

      Writing and explanations
      Draft a note, rewrite a paragraph, brainstorm, or explain a topic. Supply the facts and intended audience. Check names, claims, and details.
      Local files and small code changes
      Find and read text files, summarize notes, create text or code, and make targeted edits. Tom can run some checks on saved outputs. Large projects and long files are harder; a passing check has a limited scope.
      Simple data tasks
      Work with modest CSV, JSON, or text inputs and run a calculation to save a result. Ask Tom to show the formula and inputs. Other document formats may need an installed program that Tom can use.
      Images you share
      Describe or discuss an attached image or capture when vision is available. Small text, counting, fine details, and spatial relationships can be wrong. Tom does not continuously watch your screen.
      Programs and task steps
      Use installed programs through commands, subject to your review setting. Tom can divide work into steps and retain task records. This does not give it universal control of every Windows app.
      Web help · limited
      Attempt searches, read accessible pages, and try supported browser interactions. Browsing is currently unreliable. It can miss relevant pages, get blocked, or fail an interaction. Use it for small lookups you can verify.

      Try: “Read notes.txt in this folder. Save a five-point summary to summary.md, and list anything you could not confirm.”

      What does “capability” mean?

      A capability is an area of work supported by a set of tools and instructions. Tom has groups for files, programs, web access, task history, and planning. For example, file tools let it read actual bytes or save an actual file; being able to describe those actions in chat is different from performing them.

      The harness supplies relevant tool instructions as needed. Adding a capability gives the model another way to act; it does not retrain the model or guarantee it will choose the right action. Missing software, permission limits, incomplete evidence, and model mistakes can still prevent success.

      How do I get a better result?

      Give Tom a goal, the source material, the output location, and a way to judge the result. Keep important constraints explicit. Say whether it may edit files or run programs. For a large task, work in smaller pieces and inspect each result.

      Try: “Read expenses.csv. Total the Amount column by category. Save totals.csv beside it. Keep the source unchanged, and tell me how you checked the totals.”

      If Tom misunderstands, name the specific mismatch and point it back to the original source. Repeating a vague request with more urgency rarely supplies the missing information.

      How much should I trust Tom’s browsing?

      Browsing is one of Tom’s weaker capabilities in this build. Search results can be irrelevant or incomplete. Pages with logins, bot checks, complex layouts, or changing controls can fail. A search snippet is only a lead; it is not proof that Tom read the page or verified a claim.

      For a small lookup, provide an exact link and a specific question. Check the source, date, and relevant passage yourself. If access fails, open the page in your browser and paste the useful text into chat. Tom should tell you what it could not access. Avoid relying on it for comprehensive research or unattended website actions.

      Search and page access use the internet. The model can still run locally while a web request goes to an outside service.

      What is AI, and what is a language model?

      AI is a broad name for computer systems that perform tasks such as recognizing patterns, making predictions, or generating content. Tom uses a language model: a trained network of numerical settings that produces responses from the information supplied to it.

      For text generation, the model repeatedly predicts a next token—a word, part of a word, or another text piece. Its learned patterns can support useful writing and problem solving, but a plausible continuation can still be incorrect.

      Learn more: Google’s introduction to language models.

      Training, prompts, and learning: what changes?

      Training adjusts a model’s numerical settings using examples. Instruction tuning is further training to help it follow requests. A prompt supplies instructions or information for the current use of a model. Inference is running that model to produce a response.

      Ordinary conversation with Tom does not retrain its model. A correction can help while it is included in the task’s working context. Saved conversations and your preferred name are local records the harness can use; they are separate from the model’s trained settings.

      Learn more: Google on tuning and prompting.

      “Attention Is All You Need”—in everyday language

      This 2017 paper by Ashish Vaswani and colleagues introduced the Transformer architecture, originally evaluated on language translation. It became a foundation for many later language models. Its title does not mean that attention alone supplies facts, reliable judgment, memory, or tools.

      Think of attention as an adjustable highlighter. When processing a text piece, the network calculates how strongly to use other relevant pieces. In “The mug fell from the shelf and it broke,” relating “it” to “mug” helps interpret the sentence. The highlighter is an analogy for numerical weighting, not conscious focus.

      Several attention “heads” can learn different relationships, and layers combine and refine the information. The original design replaced recurrent sequence processing with attention-based processing, allowing more parallel work during training. Today’s models build on and modify these ideas.

      Read the original paper: Attention Is All You Need. Start with the abstract; the rest uses technical mathematics.

      Why can AI sound certain and still be wrong?

      A language model can produce convincing text without enough evidence. An invented or unsupported detail is often called a hallucination. A confident tone is not a confidence measurement. Models can also repeat biases or misleading patterns from their training data.

      Ask for sources and visible checks, then inspect them. A citation can be wrong or unrelated; a successful file save does not prove the content is correct. For consequential decisions, use qualified advice and original evidence.

      Background: Google’s language-model benefits and limitations.

      Why does the same question get different answers?

      Generated text can vary because the model may select among several possible continuations. The recent conversation, included files, available tools, model choice, and generation settings also affect its response. Repetition is not an independent fact check. For repeatable work, specify the inputs and ask for a saved calculation or check you can inspect.

      What is an AI harness, and what does Tom’s do?

      The harness is the software around the model that turns a request into an organized sequence of work. Think of a workbench with a checklist: it brings in instructions and evidence, offers tools, handles permissions, records results, and decides when to ask the model for another step.

      1. Prepare. Gather your request, relevant task notes, and available tool instructions.
      2. Ask the model. It proposes a reply or an action.
      3. Act and observe. Validate the proposed action, apply any review requirement, run the tool, and record what happened.
      4. Check and continue. Feed results back into the next step, or stop for completion, a limit, an error, or your input.

      For example, a request to summarize a file needs a real read, a model-written summary, a save, and evidence that the output exists. The harness connects those steps. It cannot guarantee that the summary preserves every important detail.

      Related background: Anthropic’s introduction to workflows, agents, and tools. Tom’s implementation is its own local harness.

      Model, chatbot, agent, harness—what is the difference?

      The model generates predictions. A chatbot presents a conversation. An agent can use a model to select actions and respond to their results. A harness manages that process. A fixed workflow follows predefined steps; agent-driven work lets the model choose more of the route. Products often mix both.

      These labels describe how software is arranged. They do not establish intelligence, independence, or reliability. Tom combines a chat interface, a local model, tools, and a harness with bounded task steps.

      What does the context ring mean?

      The ring shows the most recently measured input, including space reserved for images and formatting. It leaves room for the next reply. The number inside counts compactions in this conversation, including after a reload. It is not an accuracy score. “Not measured yet” means there is no reading to show.

      Context is the information Tom can work with in one step. Tokens are small pieces of text. Your request, recent results and the next reply share that space. When it fills up, Tom keeps shorter notes and saves the action history. Each compaction can omit or shorten details, so repeated compaction may make later replies less accurate. It does not mean accuracy drops by a fixed amount each time.

      Keep essential requirements clear, ask Tom to reread source files, and check important results. Start a fresh conversation when the topic changes. A bigger context needs more memory and can take longer to process; it does not ensure a better answer.

      Does Tom remember everything I tell it?

      No. The visible conversation, saved task record, and current model input are different things. Tom keeps local task history, but only selected material fits into a model step. Its recall tool searches the current task’s records; it does not automatically include every conversation.

      The preferred name you choose in setup or Settings is supplied to the harness. Other facts you mention are not automatically turned into a permanent personal profile. When a detail matters, restate it or point Tom to its source.

      What is the avatar showing?

      The face and label describe what Tom’s harness is doing. They are activity signals, not emotions or a view into the model’s thoughts. Green and cyan show progress, amber asks for attention, and red marks a stopped task. Ready faces and waiting dots are decorative; they do not mean Tom feels impatient.

        Where do saved files go, and how do I open them?

        The folder shown at the top of the conversation is its working directory. New conversations use the folder in Settings. Give an explicit destination if you want a file elsewhere.

        Saved-file cards show the full local path. Choose Open locally, Show in folder, or Copy path. Code opens as text; executable and unrecognized files are shown in their folder. A moved or deleted file keeps its old recorded path. A claim in chat is not a substitute for a saved-file card and the actual file.

        What does approving an action allow?

        Tom’s programs run with the launching Windows account’s access. The working folder is a starting location, not a boundary that locks tools inside it. Read the proposed command and paths before approving. Your command setting determines which execution requests require review; file operations do not all show a separate approval prompt.

        Pages and documents may contain instructions aimed at the assistant. Those are source material, not your permission to act. Review requests that do not fit your goal. A cancelled or timed-out command may already have changed something; inspect its result before trying again.

        What stays local? Does Tom need the internet?

        The model runs on this computer. Conversations, task records, your preferred name, and saved files are stored locally. Ordinary local chat and supported file work can run offline once the required model and runtime are installed.

        Web searches send a query to an external search provider, and browsing contacts the visited sites. Model downloads and model-availability checks also use the internet. Programs Tom launches may have their own network behavior. Local inference does not make every action offline or private.

        Exported task records can include your messages, file contents, and action results. Check them before sharing. People or software with access to your Windows files may also be able to read local Tom records.

        Why does startup take time, and why is chat paused?

        Tom checks its files, loads the selected model into memory, and verifies it can prepare an action. A new computer also needs initialization checks. The startup panel shows the current operation and recent activity; chat becomes available after readiness checks finish.

        The model, context, images, browser, Windows, and your other apps share RAM. A larger model or context can be slower even if it fits. Tune this computer tests available options; a benchmark does not promise that every future task will work. The model can unload while idle and needs to load again when used.

        What are Actions, task limits, Pause, and Stop?

        Expand Actions beside Tom’s name to see recorded reads, commands, results, and checks. Inspect details shows the scope of a check. Save task record exports the local history; it is not a recording of private model reasoning.

        Each request has step, text-token, and active-time allowances. These bound the amount of work; they are not a quality score. Extend budget adds another allowance while retaining work already spent. More allowance can permit more attempts without improving the result.

        Pause requests a pause at a safe step boundary. Stop interrupts work sooner. Neither undoes completed changes. An interrupted action with uncertain effects may require inspection in a new conversation instead of automatic replay.
