# Tom

A personal desktop assistant. Local Gemma 4 E2B, CPU first, with its actions in view.

**0.5.2 is an unsigned Windows beta.** Compatibility target: Windows 10/11 on 64-bit Intel or AMD, with 8 GB installed RAM recommended. Physical low-memory and older-CPU qualification is pending. Larger models require more memory and their own local checks.

Share **Tom-0.5.2-Offline-Setup.exe** on its own. It includes Tom, CPU and Vulkan engines, the E2B model, and its vision projector. After system prerequisites are installed, no internet is required to install or run the local model. **Tom-0.5.2-Network-Setup.exe** carries Tom's interface and harness and downloads pinned Node, llama.cpp, and model files directly from their original vendors. No Tom download server is required. Both install for the current account, offer portable mode, verify all files, and can repair an existing 0.5.2 installation while preserving conversations and preferences. Open Tom from Start, or double-click **Start-Tom.exe**. Remove it through Windows Installed apps or **Uninstall-Tom.exe**; personal data is retained.

## Everyday use

- Responses, action preparation, command output, verification and task checkpoints stream into one conversation. **Search the web** starts model-led research in that conversation. Search records its actual providers, queries and source reads. Conversational current-fact questions also start research. A short follow-up keeps the earlier user subject, and required queries are constrained to that subject. Automatic research uses the built-in Exa search endpoint with no extension, account, API key, or local search server. Search results are discovery evidence; Tom opens linked source pages with Playwright before answering. Google remains the default engine for browser links the user opens manually. Page text never becomes authorization.
- The avatar keeps nine harness activities with standard three-character keyboard faces, labels, subtle blinking and scanlines. Context compaction merges three lines into one. Recoverable errors/review are amber; stopped errors have red crossed-out eyes. Idle animation is capped at 8 frames per second and activity at 15; hidden pages and reduced-motion preferences stop it. Help explains all nine states. Day/night themes are available.
- The latest Tom reply has one compact header: the animated avatar and larger name, context wheel, then expandable Actions. Ready cycles through seven faces, short blinks and three waiting dots. Older replies keep the same avatar and name.
- Help includes a searchable, offline knowledge base with 21 short FAQs: practical capabilities, browsing limits, AI basics, training versus prompts, a plain-language introduction to *Attention Is All You Need*, the harness, context, privacy, files, and task controls. Topic links jump to an answer; original-source links open separately and need internet access. The smaller context ring has an always-visible help bubble.
- Setup asks **What should Tom call you?**, prefilled from the Windows account name. Settings can change it later. Only that preferred name is saved in `.state/profile.json`; the chat labels and harness use it, including after restarting or repairing Tom.
- The context wheel shows the last measured input plus image/formatting reserve; its center counts actual context-shortening steps in this conversation. Ordinary context rebuilds do not increase the count. Near-full input is highlighted and a pre-compaction event explains what happens next. The question-mark button opens Help on context, lost detail, and checking AI results. Older records without compaction telemetry are not retroactively counted.
- Saved-file cards show the full absolute local path and offer Open locally, Show in folder, and Copy path. Windows opens documents in their associated app, code as text, and selects executable or unknown formats in Explorer. The current local file opens without a browser download; moved/deleted files report an error.
- Activity stays collapsed to the current event. Expand it, then expand a specific action, result or token-usage entry. **Settings → Advanced → Record exact model input** adds the supplied text template and tokenizer IDs to the local journal. This adds storage; private generated reasoning is not recorded.
- **Ctrl Alt T** opens the Windows Ask Tom popup while the tray helper runs. Selected text is attached when the source app exposes it through accessibility. Choose a screenshot region explicitly, or paste context. **Open in Tom** creates an editable draft. **Web search** starts research and opens that task.
- Explorer file/folder menus, Send to, and Start menu entries are optional. Windows 11 Explorer currently uses **Show more options → Ask Tom**. Browser right-click menus use the included development extension. Tom cannot insert an arbitrary menu item into every other app.
- Commands are reviewed by default; read-only browser research and journal recall run directly for the requested task. Settings can enable automatic native commands. Shell and write have the launching account's access. The work folder is a starting location, not a sandbox.
- Attach, paste or drop up to two images. The model's matching vision projector loads when needed. No GPU is required.

## First run and upgrades

Startup displays a Please wait panel with the actual checklist, current operation, elapsed time, and recent activity. Every service startup loads the selected model and completes its grammar/readiness probe, including computers with saved benchmark results. Chat stays paused until that finishes. Continuing after a failed benchmark still loads and verifies the model before unlocking chat. The avatar and Help remain visible during loading; basic Help and a recovery message remain available if a UI module fails to load. Idle unloading is preserved; reopening the UI reloads an unloaded model before enabling chat.

On a new computer, Tom automatically checks E2B's loading time, CPU generation, tool formatting, context recall and image recognition when memory permits. It leaves room for Windows and stops a check if memory headroom falls too low. A failed check keeps E2B installed and explains the result.

After a passing first run, Tom checks official package availability. Offline: keep E2B. Online: offer only plausible **download and test** candidates. The screening uses measured E2B speed, free memory and disk space; its larger-model speed estimate is a heuristic, not a measured guarantee. Downloads require your button press. Pinned weights and projectors are resumable and hashed. A larger model must then pass its own CPU/text/tool/image check before **Use this model** becomes available.

**Tune this computer** repeats the checks. The extended check can qualify an 8,192-token context. Help and settings explain context as shared working space, tokens as small pieces of text, and why free RAM also needs to serve the model, images, browser and Windows. E2B is presented as a small local model with limits, with system-tested upgrades offered separately. **Settings → Advanced** offers a 2,048 minimum and the locally tested ceiling, CPU thread limits, idle unloading, and exact-input diagnostics. Longer context increases initial reading time, even if it fits memory. Upgraded models start at 4,096; they do not inherit E2B's extended-context qualification.

Hardware fingerprints stay local. Moving a larger-model installation to a different computer restores E2B unless that candidate has passed there. The displayed model identity follows the selected model. **Settings → Performance** offers Automatic, CPU, or compatible Vulkan graphics, with automatic/standard/Q8/Q4 working-memory precision. Automatic uses standard FP16 cache and tries detected graphics. A failed startup retries standard cache, then CPU, then a smaller context; the successful recovery is saved and explained. Cache support is established by a local loading and generation probe, not a GPU vendor name. Q4 remains experimental. Baseline model qualification still runs on CPU.

## Harness and task memory

The structure is a WinForms launcher/tray helper, an ordinary HTML/CSS/canvas browser interface, a small Node supervisor with SQLite, and a native llama.cpp worker. There is no Electron bundle, front-end framework, Python dependency, or separate Chromium download. The included Playwright Core module uses an installed browser.

The v2 harness loads capability descriptions as needed. Conversation begins with a small answer/capability protocol; files, programs, web, task planning and journal recall are separate modules. Actions use a strict operation grammar. Longer files use a separate content step with unpublished draft continuation, so code does not have to fit inside a JSON tool call. Related follow-ups preserve the original task, and local hardware questions receive real machine facts. File reads return short version references. Writes and exact edits retain snapshots, hash preconditions and saved-byte verification. JSON and JavaScript receive automatic parse/syntax checks; HTML writes receive a browser load check. Function code and example tests use separate focused steps, and calculations receive the same parsed data shape shown in their prompt. Passing model-selected tests is not proof of complete correctness. See [harness architecture and limits](HARNESS.md) and [repair validation](HARNESS-REPAIR.md).

Default per-request budgets: 24 model steps, 12,288 generated tokens, 15 active minutes and up to 2,048 output tokens per segment. Tom counts the formatted prompt and reserves space for the response and any images. Pausing, reviewing commands and restarting do not reset spent budget. Review waiting is excluded from active time. Each explicit **Extend budget** adds another allowance while preserving spent budget and saved jobs; a new user message starts a new request budget.

Each step uses the exact current request, a bounded selection of recent evidence, versioned file references, the current job and unmet checks. Raw messages and results remain in SQLite and can be searched or paged through task-isolated recall. Sequential jobs checkpoint after actions and survive pause/restart. Completion checks are tied to artifact/dependency versions. Interrupted writes or commands with uncertain side effects block automatic replay. Activity → Save task record exports the private inputs, operations, results, checks and budgets as JSON.

## Runtime and portability

The adapter is llama.cpp b10809, with both its universal CPU package and matching Vulkan package. Standard FP16 K/V cache and 4,096 context are the compatibility defaults, with one inference slot and up to four CPU threads. GPU offload is attempted only when a compatible device is detected. The separate RAM prompt archive is disabled; the active slot can reuse a matching prefix. Default idle unload is five minutes. Malformed settings are quarantined in the local journal, invalid performance values are repaired, and the Performance panel can restore recommended settings.

The E2B GGUF is 3,349,516,256 bytes; its projector is 986,833,664 bytes. Disk sizes are not RAM requirements. The loader screens free memory using the configured weight/projector sizes plus headroom, or the profile’s higher minimum. This is only a loading screen, not a peak-memory guarantee. Physical 8 GB qualification is outstanding; this development host has 32 GB.

GGUF describes the file format; QAT describes training. The bundled E2B file is Google's QAT Q4_0 GGUF. The model catalogue also includes a pinned E2B Q8_0 package as an optional higher-precision alternative, subject to its own local text/tool/vision checks and memory screen. These packages differ in conversion metadata and tensor counts, so their measured differences cannot be attributed to precision alone. Selecting a larger model and selecting a higher quantization precision are separate choices.

Compatibility target: Windows 10/11 x64, Intel or AMD, 8 GB RAM recommended, Windows .NET Framework 4.5 or later, and an installed supported browser. Edge is tested for Playwright; Chrome has a supported channel; Brave requires a compatibility trial and Tor automation is not implemented. The CPU package includes baseline x64 and older instruction-set variants. This is not physical qualification of every supported instruction set. ARM64, 32-bit Windows, macOS and Linux require separate packages.

Install the latest Microsoft Visual C++ x64 runtime from Microsoft before going offline. Tom 0.5.2 excludes the app-local Microsoft DLLs from earlier development builds. This system prerequisite and the installed browser retain their vendor licenses. See included license notices.

LiteRT remains a candidate for a smaller CPU package. It is not integrated here. Q8 KV caching is not Google's TurboQuant. Earlier local trials measured 33 MiB of FP16 KV buffers versus 17.53 MiB at Q8 for 4,096 context: useful, but small beside the weights. CPU speed and task quality need measurement for every runtime/cache combination.

## Data and development

`.state/tom.sqlite` holds conversations, images, events, drafts, task budgets and checkpoints. `.state/snapshots` holds previous file bytes. `.state/qualification.json` records local checks. Model logs and temporary downloads are local. `.state/session.json` contains a connection credential; keep it private. Release packaging excludes this entire directory, audits and migration references.

Both services bind to loopback with separate random credentials; the UI service validates Host and Origin. These controls do not make unrestricted tools a sandbox. Retention limits, stronger file/process isolation and broader recovery testing remain release work.

Run `runtime/node.exe scripts/check.mjs` for syntax, version and deterministic checks. `scripts/benchmark.mjs` runs production-model tasks with independent outcome checks and isolated journals. See [benchmark protocol](BENCHMARKS.md), [build instructions](BUILD.md) and [installer beta guide](INSTALLER-BETA.md). Historical scripts and audits remain development evidence, not release qualification. `scripts/build-installers.ps1` creates both shareable EXEs. `scripts/integrate-windows.ps1 -Remove` removes this installation's owned Windows entries.

Before sale: qualify a physical CPU/RAM matrix, complete task/vision evaluations, sign the distribution, finalize redistribution rights and product terms, and test accessibility and installer behavior on clean machines. Repair rolls back file replacements on ordinary errors; recovery after power loss during replacement is not yet transactional. Older multi-file preview installations need a new destination. No Nyx drive-wiping feature was incorporated or executed.

## Built-in web research

Ask a question or use Search the web. Tom sends the query to Exa’s documented public MCP endpoint using the existing Node runtime, then reads source pages through the bundled Playwright Core and installed Edge or Chrome. There is no extension pairing or service to install. The optional Ask Tom context-menu extension is unrelated to web research.

The browser search preference controls manual search links. Automated search records Exa as its provider. Search snippets can be cached, so source pages must be read before answering. Weather lookups prioritize official forecast pages. Provider rate limits are reported without requesting an account from the user. See [Exa’s documentation](https://exa.ai/docs/reference/exa-mcp) for service availability and production usage.
